Multi-Tenant Architecture

Each cafe is a tenant with a UUID. The global tenants collection stores cafe metadata; all other collections are prefixed with {uuid}_ for isolation. Logical entity references use plain UUID fields resolved via application-level joins.

tenants (global) → 550e8400_staff 550e8400_products 550e8400_orders 550e8400_invoices 550e8400_chat_messages 550e8400_salaries 550e8400_orders_details
● Global: tenants ● Tenant-Scoped: 7 collections ● Isolation: UUID prefix ● Dev Mode: bypass tenant scope

Build & Deploy

The project builds via Maven into a fat JAR using maven-shade-plugin, then wraps into a Windows .EXE via launch4j-maven-plugin. The EXE expects a bundled JRE 21+ in a jre/ directory alongside it.

mvn clean package → shade (fat JAR) → launch4j (EXE) → HanabiCafe.exe → + jre/
Data Flow
Swing UI → Service → DAO → MongoDB → POJO Codec
Login: LoginPanel → AuthService → UserDAO → tenants collection
Order: MenuItemsPanel → MenuService → OrderDAO / OrderDetailDAO / InvoiceDAO
Chat: ChatConversationPanel → ChatMessageDAO (polls every 2.5s)
Revenue: RevenuePanel → RevenueService → OrderDAO / InvoiceDAO (aggregations)
